# Actanara 主 Dashboard 信息架构

## 1. 什么才是 AI 资产

首页不再把“所有可统计的数据”都称为资产。一个对象至少满足以下条件之一，才进入资产层：

- 工作已经落盘，结果、状态和来源证据可以被重新找到；
- 从一次或多次工作中提炼出可复用的经验、决策或方法；
- 已经成为可调用、可注册或可迁移的程序性能力；
- 已经形成持久化报告、文档、生成文件或 canonical memory。

据此，Actanara 的核心资产分为：

1. **任务落盘**：完成任务、结果摘要、文件变化和直接证据形成的可回溯工作单元。
2. **学习经验**：从问题、选择、失败和结果中提炼出的 Lesson、决策与技术经验。
3. **Skill 资产**：经过复用与完整性判断，可创建、扩展或注册的程序性资产。
4. **报告与产物**：日记、周报、月报、技术进展、智慧沉淀以及持久化生成文件。
5. **可复用记忆**：经过筛选的 canonical memory，以及已进入受保护检索边界的长期知识。

## 2. 不属于资产的内容

以下内容仍然重要，但它们承担的是来源证明或系统诊断职责：

- **证据层**：Session、文件变化、工具结果、对话片段、evidence locator。
- **运行轨迹层**：Token、消息数、API 调用、缓存命中率、活跃时段、Runtime 在线状态。

证据回答“这个结论从哪里来”，运行轨迹回答“系统如何工作”；两者都不回答“最终沉淀了什么”。

## 3. 首页优先顺序

1. **资产库存**：今天和本周期真正新增了哪些资产。
2. **需要人的判断**：待复核 Skill、可结晶 Lesson、缺少证据的任务。
3. **最近沉淀**：按时间展示任务、经验、Skill、报告与记忆。
4. **来源与证据**：资产如何关联到 Workspace、Runtime、Session 和文件。
5. **运行轨迹**：Token 与活跃度降到页面下部，并提供进入专门分析页的入口。

## 4. 单个资产条目的信息顺序

1. 资产标题与资产类别；
2. 可用状态：已落盘、可复用、待复核、可注册或证据不足；
3. 一句话说明它解决了什么、为什么值得保留；
4. 证据数量、关联任务与 Workspace；
5. 来源 Runtime、Session 和形成时间；
6. Token 等运行数据仅在展开后的来源明细中出现。

## 5. 三个 Demo 的差别

- **A 星野总控台**：适合默认首页。先看资产库存和复核队列，再看最新资产，运行轨迹置底。
- **B 工作档案**：适合周报/月报与回顾场景。强调资产叙事、工作线和证据索引。
- **C AI 资产形成地图**：适合理解系统工作方式。显式展示轨迹如何经过归因和复用判断形成资产。
